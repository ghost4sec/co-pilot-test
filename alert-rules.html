Create the action group

az monitor action-group create \
  --resource-group rg-monitoring-test \
  --name ag-operators \
  --short-name ops \
  --action email on-call ops@example.com

Log search alert for role assignments

Uses the role assignment query as the alert condition.

az monitor scheduled-query create \
  --resource-group rg-monitoring-test \
  --name alert-new-role-assignment \
  --scopes <workspace-resource-id> \
  --condition "count 'q1' > 0" \
  --condition-query q1="AzureActivity | where OperationNameValue =~ 'Microsoft.Authorization/roleAssignments/write' | where ActivityStatusValue == 'Success'" \
  --evaluation-frequency 5m \
  --window-size 5m \
  --severity 2 \
  --action-groups <action-group-resource-id>

Metric alert for CPU

az monitor metrics alert create \
  --resource-group rg-monitoring-test \
  --name alert-vm-high-cpu \
  --scopes <vm-resource-id> \
  --condition "avg Percentage CPU > 85" \
  --window-size 10m \
  --evaluation-frequency 5m \
  --severity 3 \
  --action ag-operators

Good practice

  • Match severity to response time. Reserve severity 0 and 1 for events that need immediate action.
  • Use alert processing rules to suppress notifications during planned maintenance.
  • Review each rule regularly and remove alerts nobody acts on.

Command options can change between Azure CLI versions, so check the Azure Monitor alerts documentation before use. Data sources are listed on the log sources page.
